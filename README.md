# WB 签到

WorkBuddy / CodeBuddy 多账号每日自动签到 —— macOS 桌面应用（Tauri v2 + React）。

自己写的版本，只做四件事：**多账号管理 + 每日自动签到 + 积分查询与账号切换 + 本地 AI 监控（可选）**。另有一个可选的**模型摆渡**：把 OpenCode 的免费模型接进 WorkBuddy，见下。不做会话复制、Token 统计。

## 功能

| 模块 | 说明 |
| --- | --- |
| 独立授权登录 | 每个账号各走一次官方授权，在浏览器完成登录，互不影响 —— **连续登录任意多个账号**，不受「客户端同一时刻只能激活一个账号」的限制 |
| 账号管理 | 独立登录、从官方本机登录态导入、手动粘贴 access_token、删除账号 |
| 手动签到 | 单个账号签到、一键全部签到 |
| 每日自动签到 | 启动即签 + 每日兜底。App 启动时立即签一次；此后每天到达设定时刻（默认 12:00）再签一次 |
| 签到日志 | 记录每次结果，本地保留最近 500 条 |
| Token 自动续期 | 签到遇凭证失效时用 refresh_token 自动续期一次并重试 |
| **积分查询** | 查看每个账号的积分余额：总量 / 剩余 / 已用，展开可见各积分包明细（含包名与到期日）。只读操作，不消耗积分 |
| **积分趋势** | 拉取官方近 30 天逐请求用量，本地按日汇总成 14 天柱状图与「今日 / 7 日 / 30 日」每账号对照表；结果落缓存，首屏可先渲染上次数据 |
| **成长中心一键全领** | 旅行领奖 + 自动出发、盲盒按次数连抽、任务有奖即领。三个动作各自容错，单项失败不影响其余项 |
| **账号切换（保留会话）** | 在**自己已导入的账号之间**切换客户端的登录状态，可选自动重启。**开启「保留会话」后按分层快照成套切换**：登录态 + 用户目录 + 浏览器会话 + 侧边栏与当前会话路由，切完直接回到原来那条会话。切前自动备份 |
| **菜单栏常驻 + 弹出面板** | 点窗口关闭按钮**不退出程序**：窗口收起，进程留在右上角菜单栏继续跑，到点照常签到。左键点图标弹出面板，一眼看到今日签到进度与本地 AI 状态，点面板外自动收起 |
| **本地 AI 监控**（可选） | 查看本机 llama.cpp 推理后端与按需网关的实时状态、CPU / GPU 温度与运行日志。**默认关闭** —— 没部署本地 AI 的电脑保持关闭即可，关闭时不产生任何探测 |
| **模型摆渡**（可选） | 把 OpenCode 的免费模型摆渡给 WorkBuddy：内置隔离运行时、并发检测、判定缓存、一键导入。**默认关闭**，不启动时不占任何端口。需要一个 Node.js 22+ 运行时 |

## 三种添加账号方式的差别

| 方式 | 是否需要官方客户端 | 一次能加几个 | 说明 |
| --- | --- | --- | --- |
| **独立登录**（推荐） | 不需要 | 一次一个，可连续添加 | 走官方 `auth/state` → 浏览器授权 → 轮询取 token。每个账号独立授权，彼此不干扰 |
| 从本机导入 | 需要 | **只能一个** | 官方登录态文件只保存"当前登录"这一个账号的凭证，历史账号记录里**不含 token**，因此读不出凭证 |
| 手动添加 | 不需要 | 一次一个 | 自己粘贴 access_token / refresh_token |

> 因此要建多账号，用「独立登录」逐个授权即可，不需要在官方客户端里反复退出再登录。

## 安全设计

相比同类工具，这里刻意做了几处收紧：

1. **本地端口只有一个，且默认不开**。除「模型摆渡」外，前端只通过 Tauri IPC 调用命令，不存在本地 HTTP 服务。模型摆渡开启后会监听 `127.0.0.1:41980`：只绑回环、口令一次一发（`0600` 落盘）、任何带 `Origin` 的请求一律 403、请求体上限 8 MB、管理路由不对浏览器开放。这条口子是这个功能存在的前提，关掉功能就关掉端口 —— 不假装它不存在。
2. **凭证文件权限固定**。数据目录 `~/.wb-checkin` 为 `0700`，`accounts.json` / `config.json` / `checkin-logs.json` 均为 `0600`；临时文件在创建时即带 `0600`，避免 rename 之前出现可被读取的窗口。
3. **域名白名单**。账号记录里的 `domain` 必须命中 `www.codebuddy.cn` / `www.workbuddy.cn`，否则回落到默认域名 —— 防止账号记录被篡改后把 Bearer token 发往攻击者主机。手动添加时直接拒绝白名单外的域名。
4. **凭证不出后端**。前端拿到的账号视图不含 `access_token` / `refresh_token`，只有 `hasRefreshToken` 这类布尔量。
5. **无遥测**。不发起任何第三方请求，出站只有官方域名。
6. **CSP 开启**，Tauri capability 只开放核心窗口权限，不开放 shell / 文件系统 / http 插件。
7. **日志脱敏**。写入前会剔除疑似凭证的长串并截断。
8. **登录链接白名单**。独立登录时，官方返回的 `authUrl` 必须是 https 且主机名命中官方域名才会交给浏览器打开 —— 防止响应被篡改后把用户导向钓鱼页。
9. **账号库写入串行化**。后台自动签到、手动签到、导入、独立登录都会改写 `accounts.json`，全部经过同一道进程内互斥闸，避免交叠写入互相覆盖。

## 账号切换会发生什么

切换只改官方客户端的登录状态，**不影响本工具自己的账号库、签到记录与积分数据**。

执行顺序：备份现有登录态 → 关闭 WorkBuddy → 写入 → 回读校验 → 重新启动。

开启「保留会话」时会额外搬运四层现场（快照存放在 `~/.wb-checkin/profiles/<uid>/`）：登录态、账号级用户目录、浏览器会话、侧边栏与当前会话路由。复制走 APFS 写时复制，几百 MB 的会话目录也是秒级且几乎不占额外磁盘。

**需要知道的后果：**

- 勾选「自动重启」时，WorkBuddy 会被关闭再打开。**开启「保留会话」时会自动回到切换前那条会话**；未开启、或目标账号还没存过现场时，该会话仍会中断。
- 每个账号需要各存一次现场：登录该账号 → 退出客户端 → 点「保存现场」。之后才是双向可切的。
- 本工具是独立进程，切换过程中不会被关闭，会继续把写入与重启做完。
- 每次切换前都会把原登录态备份到 `~/.wb-checkin/backups/`，可手工恢复。
- 若报「无权限写入官方登录态文件」，到「系统设置 → 隐私与安全性 → App 管理」允许本 App 控制 WorkBuddy 的数据。
- 切换只影响官方客户端；本工具自己的账号库、签到与积分功能都不受影响。

## 关闭窗口会发生什么

**点窗口左上角的红色关闭按钮，程序不会退出。**

窗口只是收起来，进程继续留在右上角菜单栏运行。这是自动签到能按时触发的前提 —— 进程一旦退出，兜底时刻就没人守了。

要重新打开主界面：点 Dock 图标，或菜单栏面板里的「主窗口」。

要**真正退出**，有三个入口：面板里的「退出」、右键菜单里的「退出 WB 签到」、按 ⌘Q。

## 菜单栏面板

左键点菜单栏图标，弹出一块面板（宽 352pt，高度随内容自适应）：

| 区域 | 内容 |
| --- | --- |
| 今日签到 | 已签 / 总数、待签与失败数、下次兜底时刻、自动签到开关状态 |
| 本地 AI | 开了监控才显示：CPU / GPU 温度、内存占用条、三个服务的状态、正在推理的任务数 |
| 操作 | 立即签到 / 主窗口 / 退出 |

行为：

- **点面板以外任何地方自动收起**，和系统面板一致
- **面板开着时再点一次图标也会收起**
- 内容会自动刷新：签到概览每 10 秒、AI 状态每 5 秒；面板收起后停止轮询
- 面板独立于主窗口：主窗口收起或没打开过，面板照样能用

右键点图标仍是原生菜单（显示主窗口 / 立即签到全部账号 / 退出）—— 面板万一没弹出来，这是兜底入口。

### 刷新是怎么触发的

面板是个**常驻窗口**：弹出和收起只是显隐，webview 不重新挂载、组件不重跑 `useEffect`，
所以它不像普通窗口那样「重新打开就等于重新加载」。刷新得显式造触发点，这里用三条互为备份的路径：

| 触发 | 时机 | 作用 |
| --- | --- | --- |
| `popover-shown` 事件 | 每次弹出（后端发） | 主路径：弹出即刻拉一次全量 |
| 窗口焦点变化 | 弹出后 `set_focus()` | 事件通道万一哑掉时的兜底 |
| 定时轮询 | 开着时 AI 每 5s、概览每 10s | 面板开着不动也能看到数据在变 |
| `checkin://finished` | 后台兜底签到跑完 | 面板开着时也能跟上签到结果 |

收起时后端会发一条 `popover-hidden`，前端据此停掉轮询 —— 看不见的时候不该继续探端口、读温度。
另外还留了一条 60 秒的兜底轮询（只读本地 JSON，代价可忽略），保证任何一条链路断掉时内容也不会停在旧值上。

时间戳精确到秒（`更新于 15:41:00`）—— 秒在走，就说明刷新在跑；只显示到分钟的话，用户没法分辨
「没刷新」和「刷新了但数据没变」。

### 两个实现上的注意点

**面板位置刻意不取托盘图标的坐标。** `tray-icon` crate 在 macOS 上把 `CGDisplayPixelsHigh()` 返回的像素值当成逻辑点去翻转 y，Retina 屏（scale=2）下算出来的位置会掉到屏幕外。所以纵向锚点改用 `Monitor::work_area()`（菜单栏下沿），只有横向用鼠标点击的 x。顺带也适配了刘海屏与外接显示器。

**面板高度是量出来的。** 窗口固定宽度、高度由前端用 `ResizeObserver` 量完内容回传给后端。写死高度的话，没开 AI 监控的机器会在面板底部留一大块空白。

图标以**模板图**（template image）绘制，会跟随菜单栏深浅色自动反色，因此在新版 macOS 的深色菜单栏下同样清晰。图标由 `scripts/make-tray-icon.py` 生成，改设计重跑该脚本即可。

> 因为关闭按钮不再退出程序，如果你习惯用关闭按钮结束应用，注意它现在是「收起」。这也是为什么建议把本应用加入「系统设置 → 通用 → 登录项」，让它在开机后自动常驻。

## 本地 AI 监控（可选）

这个功能是给**部署了本地推理后端的那台电脑**用的。同一份 DMG 装到没部署的机器上，保持关闭就行 —— 这是刻意的设计：一个 app 装到多台电脑，功能按机器能力开关。

入口是主界面顶部的「本地 AI」标签页。

### 开与关

第一次切到该标签页会自动探一次本机，报告：哪些端口在监听、约定日志目录在不在、有没有 smctemp。

- 检测到部署 → 点「启用监控」
- 没检测到 → 显示「本机未检测到本地 AI 部署」，不必打开

关闭后**不再探活、不读日志、不起任何进程**；填过的路径会保留，下次打开沿用。

### 监控什么

| 服务 | 默认端口 | 探活方式 |
| --- | --- | --- |
| 按需网关（统一入口） | 8080 | **只做 TCP 探测，绝不发 HTTP** |
| 文本后端 | 8081 | `GET /v1/models` + `GET /slots` |
| 视觉后端 | 18080 | 同上 |

状态有且只有三态：**运行中** / **空闲（按需 · 正常）** / **未响应**。

网关显示「空闲」是**正常状态，不是故障** —— 它空闲约 300 秒会自行关停，下次请求再拉起（冷启动 9–29 秒）。正因为**任何 HTTP 请求都会把它唤醒**，网关的探活只验端口是否在听；「看一眼监控就把机器唤醒、白等十几秒」是必须避免的副作用。这条口径写在 `localai.rs` 顶部，改动前请先读。

端口在配置文件里（`~/.wb-checkin/config.json` 的 `local_ai.services`），默认与上面一致。

### 温度

CPU / GPU 温度由 smctemp 直读 SMC，**不需要 sudo**。程序按以下顺序查找，也可以在「监控设置」里直接填路径：

1. 「监控设置」里填的路径
2. `~/.wb-checkin/bin/smctemp`
3. `~/llama.cpp/llm-serve/smctemp`（约定位置）
4. `/opt/homebrew/bin/smctemp`、`/usr/local/bin/smctemp`、`~/bin/smctemp`

找不到时温度显示 `--`，其余功能不受影响。分档参考：`<60°C` 正常 / `60–75°C` 偏热 / `>75°C` 高温。

### 内存

菜单栏面板里的内存占用，口径与「活动监视器」的 Memory Used 一致：

```
已用 = App 内存（内部页 − 可清除页）+ 联动内存（wired）+ 已压缩内存
```

实现上直接调 mach 的 `host_statistics64` 读 `vm_statistics64`，**不起 `vm_stat` 子进程** —— 面板每 5 秒刷一次，每轮 fork 一个进程不值当。页大小从系统取（Apple Silicon 16 KiB、Intel 4 KiB），没有写死。`vm_statistics64` 的结构体布局由一个单测钉死：字段顺序或类型跟内核头文件脱节时会立刻在测试里暴露，不会等到线上读出乱数。

进度条按占用率分档：`<70%` 正常（墨绿）/ `70–90%` 偏紧 / `>90%` 吃紧。读不到时**整行不显示**（与温度显示 `--` 的处理不同）—— 只有一半数字的行不如不显示。这个指标目前只在菜单栏面板上，主界面的「本地 AI」页没有放。

### 运行日志

默认读 `~/llama.cpp/logs`，可在「监控设置」里改（支持 `~` 前缀）。行为：

- 列出该目录下所有 `.log` / `.txt`，**按最近写入排序**；
- 只回读文件末尾 64 KB，不会把几十 MB 的推理日志整个读进内存；
- 自动剥离 ANSI 颜色码，去掉末尾空行；
- 日志框默认跟随滚动；**手动往上翻时会停止跟随**，切文件后恢复。

读取范围是严格受限的：只接受该目录下的单层普通文件。路径分隔符、隐藏文件、白名单外的扩展名一律拒绝；符号链接指向目录外也会被 `canonicalize` 比对拦住。这几条都有单测覆盖。

### 与前身脚本的关系

本功能移植自独立的 `ai_status_dashboard.py`（浏览器仪表盘，绑定 `127.0.0.1:18700`）。两处刻意的差异：

1. **不再需要 Python**。逻辑用 Rust 重写进进程内，装机只装一个 app。
2. **不再另起本地 HTTP 服务**。那个面板没有鉴权，同机任何进程或网页都能调用它的接口；现在前端只走 Tauri IPC，这个攻击面不存在。

## 模型摆渡（可选）

把 OpenCode 的免费模型摆渡给 WorkBuddy。**默认关闭**，开关在「模型摆渡」标签页。

### 它是怎么工作的

```
WorkBuddy → 127.0.0.1:41980 → 隔离的 opencode serve → OpenCode Zen 免费模型
```

转发口把 WorkBuddy 的 OpenAI 请求翻译成 opencode 的「会话 + 消息」，工具调用以 JSON 信封表达；本机动作一律拒绝或转交，模型不会自己动手。运行时是一个**内置的 Node sidecar**（`sidecar/`，来自 OC Ferry，MIT），应用负责它的生死。

### 开关与状态

| 动作 | 说明 |
| --- | --- |
| 启动 / 停止 | 启动会拉起 sidecar 与它自己的 opencode，首次运行可能要下载运行时（约 70 MB） |
| 检测全部 | 忽略判定缓存，强制重测每一个模型 |
| 导入 WorkBuddy | 把可用模型写进 `~/.workbuddy/models.json`，只增删带 `oc-ferry-v1` 标记的条目 |
| 每行的开关 | 该模型是否纳入导入 |

状态列会直说原因：**可用** / **可用·仅对话**（工具调不通，已关掉工具）/ **地区限制**（403，按出口 IP 判定）/ **已下线**（410）/ **超时**。

### 这一版相对上游改了什么

拿到的是 OC Ferry 0.2.9 的代码，在 `sidecar/` 里打了七处补丁：

| 改动 | 原因 |
| --- | --- |
| **运行时自愈** | 原来 opencode 子进程一退出就整套收摊，WorkBuddy 侧全部变成 ECONNREFUSED；现在先退避重启（1/2/4/8/15 秒），并在子进程还活着但健康检查连续失败时也按崩溃处理 |
| **检测提速** | 超时 60 秒 → 30 秒、并发 3 → 6。本机实测一轮 12 个模型从最坏 3 分钟降到 1 分钟量级 |
| **判定缓存不去翻新** | 指纹里去掉 context/output 两个数值。上游改一次上下文上限就让整份缓存作废（日志里 `probe cache hit 0` 反复出现），而这两个数字并不影响「能不能产生工具调用」 |
| **403/410 缓存 24 小时** | 地区限制与下线是长期策略，按 1 小时重试等于每轮都白等一次 |
| **审批不再轮询** | 250 ms 一次 `GET /permission` 改成事件驱动 + 5 秒兜底；本机日志里 11 个监听器的堆积警告就此消失 |
| **无工具请求改走纯文本通道** | 以前任何请求都要套 JSON 信封，而结构化输出必须整段合法才会吐出（实测 4～9 秒一次性到达）。现在没带工具的请求直接走纯文本并**边生成边下发**：实测一次回答切成 59 个分片、首字 4.5 秒、总耗时 5.2 秒 |
| **不把推理当正文** | `message.part.delta` 对推理段和正文段的 `field` 都是 `text`，不加区分会把模型的思考过程流给用户。按 part 类型过滤后只剩正文 |
| **思考模式自动改投纯文本信封** | 上游拒绝「思考模式 + 强制 tool_choice」，而结构化输出正是靠强制 tool_choice 落地的 —— 两者在一次请求里不能共存（实测报 `Thinking mode does not support this tool_choice` 直接 400）。现在捕获这条错误后去掉 `format`、换成「把同一份 JSON 当正文返回」，同一个模型只降级一次并记住 |

带工具的请求仍走「信封校验通过再交付」：工具调用必须先完整合法才能执行，这一点没有妥协。实测这类请求的上游输出是一次性到达的（结构化输出不会被增量下发），所以信封模式下的流式开关 `FERRY_STREAM_ENVELOPE` 保持关闭 —— 打开也不会多出一个字。

### 需要知道的

- **需要一个 Node.js 22+ 运行时**。应用不打包 Node：找不到时启动会直接报「未找到 Node.js 22+」，不会留下半死的进程。可用 `WB_FERRY_NODE` 指定路径。
- **端口只有一个主人**。独立版 OC Ferry 若还开着，请先退出它，否则会提示端口被占用 —— 两个实例同时改 `models.json` 必然互相覆盖。**但自己留下的进程会被认领**：客户端崩溃或被强杀时 sidecar 会过继给 launchd 继续占着 41980，下次启动按 `service.pid` 认出它并直接接管（版本不一致则先停掉再起新的），不会出现「显示已停止 → 点启动说端口被占用 → 点停止说没在运行」的死锁。
- **出口 IP 被限流是可恢复的**。上游偶尔返回 `abusive traffic from this IP address`，这是链路级临时限制，不是模型权限问题：面板标「IP 受限」并按 10 分钟重试，本轮检测提前收队，**模型也不会因此被撤下清单**——否则每失败一次少一个模型，等清单空了就再没有请求能把它加回来。
- **首次启动会接管独立版的现场**：沿用它的 `api-key`（否则 `models.json` 里已导入的条目会 401）与 `settings.json`（你手动关掉过的模型清单）。
- **免费模型由上游决定**，随时可能收紧或下线。这一栏不承诺可用性。
- **「系统代理」开关只跟随、不配置**。它读的是 macOS 里已经配好的**手动 HTTP/HTTPS 代理**（`scutil --proxy` 里 `HTTPSEnable=1`）；机器上没有代理时开关直接点不动，面板会写明原因，而不是让你点一下再弹一个错。PAC 与 SOCKS 拿不到可用的转发口，不支持。它只改本模块的出口、不动系统设置，**也不改变上游对出口 IP 的地区与频次判定** —— 被 IP 挡住时，开关开与关的结果完全一样。
- **代理消失不会拖垮服务**。曾经开着「跟随系统代理」、之后 macOS 那边的代理被关掉（换了网络、退了客户端），启动时会自动降级为直连、把开关落成关、把原因写进 `opencode.log`，服务照常起来。反之，启动失败时死因会同时写进日志与 `status.json`，面板的报错里直接带出来，不会只剩一句「进程已退出」。
- **地区限制换客户端也解不掉**：OpenCode 官方文档明确写着部分模型不对中国大陆等地区开放，这是按出口 IP 判定的策略。本工具如实归因、自动落到可用模型，不做身份伪造。

## 安装到其他 Mac（务必先读）

本工具没有 Apple 开发者签名，属自编译产物。把 DMG 拷到别的电脑后双击，可能遇到**「WB-Checkin」已损坏，无法打开，你应该将它移到废纸篓**。

**这不是文件真的坏了**，是两道机制叠加：

1. **Gatekeeper 隔离属性**。文件经 AirDrop / 微信 / 浏览器 / U 盘传输后会被打上 `com.apple.quarantine`。本机直接构建的产物没有这个属性，所以本机双击正常；一旦带上它，系统就会在启动前对 app 做静态校验。
2. **bundle 签名结构**。仅给可执行文件做链接期签名（`linker-signed`）、而没给整个 `.app` 重新签名的产物，`Info.plist` 与 `Resources/` 不参与封印。校验时判定「签名声称包含资源，但实际没有」→ 直接归为**损坏**，此时「仍要打开」按钮无效。

### 解决（三种任选其一）

```bash
# 方式一：命令行清除隔离属性（最彻底，推荐）
sudo xattr -cr /Applications/WB-Checkin.app

# 方式二：若还挂在 DMG 卷里没拷出来
xattr -cr "/Volumes/WB-Checkin/WB-Checkin.app"

# 方式三：图形界面
# 系统设置 → 隐私与安全性 → 找到「已阻止使用 WB-Checkin」→ 点「仍要打开」
```

> 方式三**只在 0.1.1 及以后的版本上有效**。0.1.0 的产物签名结构损坏，系统不会给出「仍要打开」选项。
> 方式一在任意版本上都能生效。

### 版本差异

| 版本 | bundle 签名 | 另一台电脑的表现 |
| --- | --- | --- |
| 0.1.0 | `linker-signed`，仅可执行文件签名，`Sealed Resources=none` | 报**已损坏**，且无「仍要打开」选项，只能靠 `xattr -cr` |
| 0.1.1+ | 完整 `adhoc` 签名，`Info.plist` 与 `Resources` 纳入封印 | 清除隔离属性后可直接运行；未清除时也有「仍要打开」可选 |

0.1.1 起在 `tauri.conf.json` 设置了 `bundle.macOS.signingIdentity: "-"`，Tauri 打包时会自动对整个 bundle 做 adhoc 签名，不再产出结构损坏的包。

### 验证产物签名是否合格

```bash
codesign --verify --deep --strict -vv /Applications/WB-Checkin.app
# 期望输出：valid on disk / satisfies its Designated Requirement
# 若输出 "code has no resources but signature indicates they must be present"，即是本次那个 bug
```

## 用到的接口

签到、积分、账号资料均通过官方客户端的接口调用，鉴权使用账号自己的 token。请求清单与参数不在此展开。

## 注意

- 自动签到需要 App 处于运行状态。建议把 App 加入「系统设置 → 通用 → 登录项」。
- 签到一天只有一次机会，所以不做高频轮询：只在启动时与每日兜底时刻各跑一轮。兜底时刻若 App 没在运行，下次启动就会补上，不会漏掉当天的签到。
- 兜底那一轮若失败（断网、凭证失效等），当天不会自动重试，需在界面上手动签到，或关闭后重新打开 App 触发启动即签。
- 未填 `refresh_token` 的账号，token 过期后需要重新粘贴，无法长期无人值守。
- 已导入的账号与官方客户端各自持有独立的 token 副本，客户端退出登录不影响本工具；但两边共享同一条 refresh 链，若服务端开启 refresh token 轮换，任一侧刷新会让另一侧手里的 refresh token 作废。
- 积分查询走的是官方套餐页那组接口，属于只读调用，既不消耗积分也不影响签到；但接口并非公开文档化的契约，官方若调整路径或字段，余额会显示为查询失败（账号本身不受影响）。
- 切换账号用的是**账号库里的凭证**，与客户端当前登录的是哪个账号无关；因此要先确保目标账号已被导入本工具。
- 本地 AI 监控是**只读**的：只建 TCP 连接、只调后端自己的只读接口、只读日志文件，不写入、不启停任何服务。
- 监控每 2 秒刷新一次，但只在**窗口可见且停在「本地 AI」标签页**时轮询；窗口收起、切到别的标签页、或 App 在后台时都会停止，切回来立即恢复。
- 监控依赖本机路径与端口。把 App 装到另一台电脑后，「监控设置」里的路径若不同，需要重新填一次；日志目录与 smctemp 的约定位置在多台机器上一致时可留空。
- 本项目为个人自用工具，非官方产品。
